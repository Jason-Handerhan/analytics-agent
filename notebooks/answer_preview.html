Order Volume Heatmap: Day of Week × Hour of Day

This is built from order counts (distinct orders, not order-lines) grouped by order_dow and order_hour_of_day in product_order_analysis. The pattern is clear: order volume is lowest overnight (roughly midnight–6am across every day), ramps up sharply starting around 7–8am, and peaks in the late morning through mid-afternoon (roughly 10am–3pm), with Sunday and Monday showing the heaviest volumes overall.

Yes — a similar chart already exists in the codebase

The Preliminary EDA notebook (Notebooks/EDA/preliminary_eda.ipynb) builds essentially the same visualization under the heading "Day of Week & Time of Day Order Density Heatmap," titled "Order Density: Day of Week vs Hour of Day." It's one of the project's documented key findings — order density peaks Sunday afternoons and Monday mornings — which directly motivated including cyclical/temporal features (day-of-week and time-of-day affinities) in the downstream feature engineering pipeline.

Here's the actual code from that notebook:

# Get order count by day of week and time of day
time_bf = bf_orders.groupby(['order_dow', 'order_hour_of_day']).size().reset_index()
time_bf.columns = ['order_dow', 'order_hour_of_day', 'order_count']

# Convert to pandas and pivot data
time_pd = time_bf.to_pandas()
plot_matrix = time_pd.pivot(index='order_hour_of_day', columns='order_dow', values='order_count')

# Fill nulls with 0 and convert to float
plot_matrix = plot_matrix.fillna(0).astype(float)

# Create list for day of week labels
day_labels = ['Sunday', 'Monday', 'Tuesday', 'Wednesday', 'Thursday', 'Friday', 'Saturday']

plt.figure(figsize=(12, 8.5))
sns.heatmap(plot_matrix, cmap='YlGnBu', xticklabels=day_labels, yticklabels=True, cbar_kws={'label': 'Total Orders'})
plt.title('Order Density: Day of Week vs Hour of Day', fontsize=14, pad=15)
plt.xlabel('Day of Week', fontsize=12)
plt.ylabel('Hour of Day (24hr Clock)', fontsize=12)

# Invert the y-axis so it starts with 0
plt.gca().invert_yaxis()

plt.show()

One difference worth noting: this notebook version uses bf_orders (the raw, BigFrames-loaded orders table, counted via .size() per group — i.e. order-line/order count straight from source) while the chart above was built from the product_order_analysis warehouse table using COUNT(DISTINCT order_id). Both approaches land on the same underlying order-level grain, so the shapes match.
