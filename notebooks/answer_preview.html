How Feature Importance Is Calculated

The project uses SHAP (SHapley Additive exPlanations) to decompose each individual prediction into per-feature contributions, then averages the absolute value of those contributions across many predictions to get a global importance ranking. From the project's model_evaluation.ipynb notebook:

1. Computing raw SHAP values — tree models are handled differently because XGBoost exposes a native contribution API, while LightGBM goes through the shap library (with a GPU-accelerated explainer, falling back to CPU if unavailable):

# 1. Calculate SHAP values
if 'xgboost' in name:
    booster = model.get_booster()
    dmat = xgb.DMatrix(X_sample)
    contributions = booster.predict(dmat, pred_contribs=True)
    shap_values_raw = contributions[:, :-1]
    base_value = contributions[0, -1]

elif 'lgbm' in name:
    lgb_booster = model.booster_
    try:
        explainer = shap.GPUTreeExplainer(lgb_booster)
        shap_values_raw = explainer.shap_values(X_sample)
    except Exception as e:
        print(f"⚠️ GPU Explainer unavailable for {display_name}, falling back to CPU TreeExplainer...")
        explainer = shap.TreeExplainer(lgb_booster)
        shap_values_raw = explainer.shap_values(X_sample)
    base_value = explainer.expected_value

2. Aggregating into a global importance score — exactly the number shown in the chart above (mean_absolute_shap) is just the average magnitude of each feature's row-level SHAP value across the sampled predictions:

# Compute the global mean absolute SHAP value exactly like the barplot does
mean_abs_shap = np.abs(shap_values_raw).mean(axis=0)

agg_df = pd.DataFrame({
    'split': dataset_split,
    'model_id': name,
    'model_name': display_name,
    'feature_name': features,
    'mean_absolute_shap': mean_abs_shap
})

This was computed on a sample of up to 150,000 rows per model/split (to keep memory manageable on an interpretability run covering millions of predictions), with row-level SHAP detail streamed to BigQuery in 2,000-row chunks for the dashboard's beeswarm visuals.

What the Docs Conclude

The project's own write-up draws a few consistent conclusions from this feature importance work:

  • Timing/cyclical features dominate: "Days Since Last Purchase" and "Avg Days Between Product Purchases" are a strong indicator of when a customer is ready to reorder a product — which matches exactly what we see for the XGBoost Ranker above.
  • Streak features define buying momentum: features like "Consecutive Product Order Skips" and "Last 3 Orders Purchase Streak" capture whether a customer has been consistently buying or skipping a product.
  • Concentration/penetration features represent loyalty: how much of a user's history, and how large a share of their orders, a given product occupies.
  • Rankers vs. Classifiers differ systematically: classifiers tend to lean more heavily on streak and penetration-ratio features to predict probabilities, while rankers (like the XGBoost Ranker shown here) place greater weight on cyclical timing features and purchase concentration.
  • Consistency builds confidence: the same feature categories show up as important across all four base models and across both the validation and test splits, which the authors interpret as evidence the models are picking up genuine behavioral signal rather than overfitting to noise.

Note: the methodology description and its stated conclusions come from the project's own documentation, not a live query — they describe the approach, not a verifiable live number. All numeric values in the table above come from a live DAX query against the dashboard's semantic model this turn.
